Call Analysis API

v1 — Recorded Calls

Overview

This API analyzes a recorded call and returns emotion scores (anger, happy, neutral, sad) over time. Submit a call's audio, then poll for the result or receive it via a webhook once processing completes.

This API covers recorded/post-call audio only. Live, real-time analysis during an in-progress call is in active development and not yet available — there is no committed date for it yet. Submitting a call recording as soon as it ends is fully supported today.

Authentication

Every request requires an API key, provided to you separately, sent as a header:

X-API-Key: <your key>

Requests without a valid key return 401.

1. Submit a call

POST /api/external/v1/calls
X-API-Key: <your key>
Content-Type: audio/wav
X-Callback-Url: https://your-server/webhook   (optional)

Body: raw WAV audio — mono, 8kHz, 16-bit PCM, max 50MB.
This is the exact format required; audio is not resampled on our side, so
files at other sample rates will be rejected, not automatically converted.

Validation happens immediately on upload — if the file isn't in the expected format, you get a 400 back within about a second, not after the job has been queued.

Response — 202 Accepted:

{ "callId": "call_8f3a1c2e9b7d4f61", "status": "queued", "durationSec": 274.4 }

2. Check status / get the result

GET /api/external/v1/calls/{callId}
X-API-Key: <your key>

Response:

{
  "callId": "call_8f3a1c2e9b7d4f61",
  "status": "processing",
  "durationSec": 274.4,
  "progress": 0.42,
  "chunks": [
    { "tSec": 0, "anger": 0.05, "happy": 0.10, "neutral": 0.80, "sad": 0.05 },
    { "tSec": 3, "anger": 0.03, "happy": 0.02, "neutral": 0.55, "sad": 0.40 }
  ],
  "error": null
}
  • status is one of queued, processing, completed, failed.
  • chunks fills in progressively while status is processing — you don't need to wait for completed to start rendering a graph.
  • Each chunk covers a 3-second window of the call, starting at tSec.
  • When status is failed, error contains a short message; chunks will contain whatever was completed before the failure.

3. Webhook (optional, recommended)

If you included X-Callback-Url when submitting the call, we POST the final result to that URL once the job reaches completed or failed:

{
  "callId": "call_8f3a1c2e9b7d4f61",
  "status": "completed",
  "durationSec": 274.4,
  "chunks": [ ... ],
  "error": null
}

The request includes a signature header so you can verify it came from us:

X-Signature: sha256=<hmac>

The HMAC is computed over the raw JSON body using your API key as the signing secret (SHA-256). Verify it before trusting the payload.

Delivery retries: if your endpoint doesn't respond with a 2xx status (or doesn't respond within 10 seconds, which we count as a failure), we make up to 4 total delivery attempts: immediately, then after 1 minute, 5 minutes, and 30 minutes. If all 4 fail, we give up and log it — there is no further retry after that.

You may receive the same webhook twice. If your endpoint processes the payload successfully but responds slowly (past our 10-second timeout), we count that attempt as failed and retry it, which can result in you receiving the same callId payload more than once. Deduplicate on callId to handle this safely.

Because the retry window (up to ~36 minutes) is not unlimited, poll GET /api/external/v1/calls/{callId} as a fallback if you rely on the webhook and suspect a delivery issue, or if it's been a while and you haven't received it.

Errors

All errors use one consistent shape:

{ "error": { "code": "invalid_audio_format", "message": "Expected mono 8kHz WAV" } }
HTTP StatusCodeMeaning
400invalid_content_typeContent-Type header wasn't audio/wav
400invalid_audio_formatFile isn't valid mono/8kHz/16-bit WAV
401missing_api_keyNo X-API-Key header sent
401invalid_api_keyX-API-Key doesn't match a known key
404unknown_call_idNo job exists with that callId for your key
413payload_too_largeFile exceeds the 50MB limit
429too_many_queued_jobsMore than 5 jobs already queued/processing for your key
500 / 502internal_errorSomething failed on our end — safe to retry

Limits & current scope

  • Recorded calls only. No live/streaming support yet.
  • Max file size: 50MB per call.
  • Max 5 jobs queued/processing at once per API key — submit more once earlier ones complete.
  • Processing time is roughly equal to the call's length. In testing, a 274-second (~4.6 minute) call took about 248 seconds to fully process. Longer calls take proportionally longer; this is not instantaneous, and progress should be shown as the job works through the call.
  • Results are retained for 7 days after completion, then deleted.
